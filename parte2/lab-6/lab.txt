Laboratório: Produtor–Consumidor
Mutex, variáveis de condição e semáforos POSIX
Exercício elaborado com apoio de formatação do ChatGPT
Objetivo
Implementar e analisar três soluções para o problema clássico do produtor–consumidor,
utilizando diferentes mecanismos de sincronização.
O laboratório procura distinguir dois problemas fundamentais da programação concorrente:
• Exclusão mútua: evitar condições de corrida (race conditions) no acesso aos dados
compartilhados.
• Sincronização por disponibilidade de recursos: impedir que o produtor deposite itens
em um buffer cheio ou que o consumidor retire itens de um buffer vazio.
Descrição geral do problema
Considere duas tarefas que compartilham um buffer circular de tamanho N:
• Produtor: gera uma sequência de números inteiros de 1 até TOTAL e os deposita no
buffer.
• Consumidor: retira os itens do buffer, respeitando a ordem em que foram produzidos
(FIFO).
O buffer deverá ser implementado utilizando um vetor de inteiros e variáveis que permitam
controlar as posições de entrada e saída e a quantidade de itens armazenados.
Utilize inicialmente:
1 #define N 5
2 #define TOTAL 20
O programa deverá apresentar os valores produzidos e consumidos e, quando aplicável, a
quantidade de posições ocupadas no buffer.
As três implementações deverão utilizar as mesmas características gerais, permitindo com-
parar os mecanismos de sincronização empregados.
1 Produtor–Consumidor utilizando mutex
Implemente o problema produtor–consumidor utilizando exclusivamente um mutex como
mecanismo de sincronização. Utilize o tipo pthread_mutex_t.

Requisitos
1. Criar uma thread produtora e uma thread consumidora utilizando pthread_create().
2. Implementar um buffer circular de tamanho N.
3. Utilizar um único mutex para proteger as operações necessárias sobre os dados com-
partilhados.
4. Impedir que o produtor deposite um item quando o buffer estiver cheio.
5. Impedir que o consumidor retire um item quando o buffer estiver vazio.
6. Liberar o mutex quando uma operação não puder ser realizada, permitindo que a outra
thread prossiga.
7. Proteger individualmente cada operação de inserção ou remoção.
8. Não utilizar semáforos, variáveis de condição, sched_yield(), sleep() ou usleep().
Questões para análise
1.1. Identifique as variáveis compartilhadas entre as threads. Quais delas podem provocar
condições de corrida? Justifique.
1.2. Explique como o mutex evita condições de corrida no acesso ao buffer e às variáveis de
controle.
1.3. O mutex também resolve o problema da disponibilidade de recursos? Explique como o
programa trata as situações de buffer cheio e buffer vazio.
1.4. O que aconteceria se o produtor mantivesse o mutex adquirido enquanto aguardasse
uma posição livre? Analise também o caso equivalente do consumidor.
1.5. A solução utiliza espera ativa (busy waiting)? Explique seu funcionamento e suas con-
sequências para a utilização da CPU.
1.6. Para produzir ou consumir um item, quantas vezes uma thread pode precisar adquirir o
mutex? Justifique.
2 Produtor–Consumidor utilizando mutex e variáveis de condição
Modifique a implementação do Exercício 1 para utilizar um mutex e duas variáveis de con-
dição (pthread_cond_t).
As variáveis de condição deverão representar as seguintes situações:
• nao_cheio: existência de espaço disponível para o produtor.
• nao_vazio: existência de pelo menos um item disponível para o consumidor.
Requisitos
1. Manter o buffer circular e as duas threads do exercício anterior.
2. Utilizar o mutex para proteger os acessos necessários aos dados compartilhados.
3. Utilizar pthread_cond_wait() para bloquear o produtor quando o buffer estiver cheio.
4. Utilizar pthread_cond_wait() para bloquear o consumidor quando o buffer estiver
vazio.

3 Produtor–Consumidor utilizando semáforos
Implemente uma terceira versão do problema utilizando semáforos POSIX (sem_t).
Nesta implementação, deverão ser utilizados três semáforos:
• vagas: representa a quantidade de posições livres no buffer.
• itens: representa a quantidade de itens disponíveis para consumo.
• exclusao: semáforo binário utilizado para garantir exclusão mútua.
Requisitos
1. Utilizar sem_init(), sem_wait(), sem_post() e sem_destroy().
2. Inicializar corretamente os três semáforos.
3. Bloquear o produtor quando não houver posições disponíveis no buffer.
4. Bloquear o consumidor quando não houver itens disponíveis.
5. Garantir exclusão mútua nas operações necessárias sobre o buffer.
6. Não utilizar mutex, variáveis de condição, espera ativa, sched_yield(), sleep() ou
usleep().
Questões para análise
3.1. Quais devem ser os valores iniciais dos três semáforos? Justifique.
3.2. Explique como os semáforos vagas e itens controlam a disponibilidade de recursos.
3.3. Qual é a função do semáforo exclusao? Ele resolve o mesmo problema que os outros
dois semáforos?
3.4. Analise o que poderia acontecer se o produtor executasse sem_wait(&exclusao)
antes de sem_wait(&vagas). Considere também a situação equivalente no consumidor.
3.5. Considerando apenas um produtor e um consumidor, seria possível eliminar o semáforo
exclusao, mantendo somente vagas e itens? Justifique.
